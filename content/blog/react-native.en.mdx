**[React Native](https://reactnative.dev/) is Meta's open-source framework for building Android and iOS apps from one [JavaScript](https://developer.mozilla.org/en-US/docs/Web/JavaScript) or TypeScript codebase using React.** Unlike a web app wrapped in a shell, the components you write become the platform's own native views at runtime. Since React Native 0.82 (October 2025) every app runs on the **New Architecture** — JSI, the Fabric renderer and Turbo Native Modules — which removed the old asynchronous bridge behind most historical performance complaints.

It is the natural choice for a team that already writes React. On our published rate card, a React Native app costs the same as any cross-platform build: **$5,000–$15,000** for a simple app up to **$45,000–$100,000** for an advanced platform, as of November 2026.

## What is React Native?

React Native is an open-source framework from Meta built on the [React](https://react.dev/) library. You write your interface with familiar React components, and React Native renders them with the operating system's own UI elements rather than HTML.

The official [Core Components documentation](https://reactnative.dev/docs/intro-react-native-components) spells out the mapping: "At runtime, React Native creates the corresponding Android and iOS views for those components."

| React Native component | Android view | iOS view |
|---|---|---|
| `<View>` | `ViewGroup` | `UIView` |
| `<Text>` | `TextView` | `UITextView` |
| `<Image>` | `ImageView` | `UIImageView` |
| `<ScrollView>` | `ScrollView` | `UIScrollView` |
| `<TextInput>` | `EditText` | `UITextField` |

This is what separates React Native from older WebView-based hybrid apps, which were websites running inside an app shell. The difference between the categories is covered in [Native vs Hybrid Apps](/en/blog/native-vs-hybrid-app).

## How React Native works (the internal architecture)

Your application logic — calculations, state, network calls — runs as JavaScript. The interface is drawn by native views on the platform's UI thread. What matters is how the two talk to each other.

### The old architecture: the asynchronous bridge

In the original design, JavaScript and native code communicated over a **bridge**. As the React Native team describes it, rendering a component or calling a native function meant serialising the call and enqueuing it on the bridge, to be processed asynchronously. That caused bottlenecks with frequent updates and large objects, made 60+ FPS hard to reach, and produced bugs such as lists briefly showing empty space during fast scrolling.

### The New Architecture: now the only one

The New Architecture was available as an opt-in from React Native 0.68, became the **default in 0.76 (October 2024)**, and since **[React Native 0.82](https://reactnative.dev/blog/2025/10/08/react-native-0.82) (October 2025)** is the only architecture — setting `newArchEnabled=false` on Android or `RCT_NEW_ARCH_ENABLED=0` on iOS is now ignored. React Native 0.81 was the last version that allowed the legacy architecture.

According to [The New Architecture is Here](https://reactnative.dev/blog/2024/10/23/the-new-architecture-is-here), it consists of:

- **JSI (JavaScript Interface):** direct communication between JavaScript and native code, replacing the bridge. Native modules can now be called synchronously and return values that reference native objects.
- **The new renderer (Fabric):** stores the view hierarchy in an immutable tree, so React can work on several versions of the UI at once, interrupt a low-priority update for urgent input, and read layout synchronously in `useLayoutEffect` before the user sees a frame.
- **Turbo Native Modules:** modules are loaded lazily, only when they are actually needed, rather than all at startup.

**What this means in practice:** performance criticism written against the bridge-era framework describes something that no longer ships. Evaluate React Native on its current version, not on a post from before 2024.

Development also moves quickly thanks to [Fast Refresh](https://reactnative.dev/docs/fast-refresh): most edits are visible "within a second or two", and React local state in function components is preserved by default.

## Advantages of React Native

- **One codebase for two platforms**, with platform-specific code only where you need it.
- **Reusable team expertise:** React web developers already know the component model, hooks, state libraries and tooling.
- **Shared business logic** between web and mobile (validation, data models, API clients).
- **Large ecosystem:** the npm registry plus mature libraries for navigation, state and animation.
- **Over-the-air updates:** [Expo's EAS Update](https://docs.expo.dev/eas-update/introduction/) can update an app's "non-native pieces (such as JS, styling, and images)" without a store submission. Native code, native dependencies, permission changes and SDK upgrades still need a new binary, and updates must follow App Store and Play Store guidelines.
- **Native code escape hatch** for any component that needs bespoke performance or a platform API.

## Limitations of React Native

- **Very heavy graphics or media:** 3D games, live video processing or complex real-time graphics are better served by native code or a game engine.
- **Third-party dependency:** some OS capabilities are only available through community packages, whose maintenance can lag.
- **App size:** the JavaScript engine ships inside the app, so a minimal React Native app is larger than a bare native one.
- **Upgrades:** moving between versions takes deliberate work — the 0.82 switch, for example, required every library you use to support the New Architecture.
- **New OS features arrive late:** a new iOS capability may need a native module before you can use it.
- **RTL needs attention:** right-to-left layout is governed by [`I18nManager`](https://reactnative.dev/docs/i18nmanager), whose RTL switches only apply once the app has been relaunched; the documentation also recommends keeping `forceRTL` for development and testing. Arabic-first apps should design their language switching around this — see [Arabic and RTL in React Native](/en/blog/react-native-rtl-arabic).

## React Native or Flutter?

React Native maps your components to native views and suits teams that already write React or want to share code with a React web app; [Flutter](/en/blog/flutter) draws its own widgets in Dart and suits fresh teams and products that need a pixel-identical design system. The full side-by-side, with a decision framework, lives in [Flutter vs React Native: Which Should You Choose?](/en/blog/flutter-vs-react-native). Framework selection is also one of the first things we settle when scoping [mobile app development](/en/services/mobile-apps) for a client.

## When not to use React Native

Avoid it if your project is:

- **A game** — use Unity or Godot.
- **Heavily media-processing**, such as video editing or real-time camera effects.
- **A simple app for one platform only** — Swift or Kotlin alone will be lighter.
- **Dependent on brand-new OS features at launch** — waiting for module support will block you.

## Frequently asked questions

### Is the React Native bridge still used?

No. Since React Native 0.82 the New Architecture is the only architecture, and the flags that used to switch back to the legacy bridge are ignored. Some legacy APIs remain in the codebase for compatibility, and interop layers will stay for the foreseeable future, but apps run on JSI and the new renderer.

### Which version made the New Architecture the default?

React Native 0.76, released in October 2024. It had been available as an opt-in since 0.68; 0.81 was the last version that let you turn it off, and 0.82 (October 2025) removed that option.

### Can I push a fix without App Store or Play Store review?

Partly. With Expo's EAS Update you can ship changes to JavaScript, styling and images over the air. Changes to native code, native dependencies or permissions require a new build through the stores, and updates must still respect store guidelines.

### How much does a React Native app cost?

From our published rate card, as of November 2026: $5,000–$15,000 for a simple app, $15,000–$45,000 for a mid-complexity app, and $45,000–$100,000 for an advanced app or platform. Backend scope and integrations move the figure more than the framework.

### How does React Native handle Arabic right-to-left layouts?

Through the `I18nManager` module, which exposes `isRTL` and lets you allow or force a right-to-left layout. Those settings persist but are applied on the next launch, so an in-app Arabic/English switch has to relaunch the app. Icons, animations and some third-party components need checking in RTL.

### Can React Native code be shared with a website?

Validation rules, data types and the code that calls your API carry over well to a React web app. Sharing the UI itself is possible through community projects such as React Native Web, which is best suited to app-like screens rather than marketing pages.
