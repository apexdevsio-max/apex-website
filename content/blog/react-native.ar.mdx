![شعار React Native وواجهة تطبيق على جوالين](/images/blog/react-native/react-native-hero-banner.jpeg)

**[React Native](https://reactnative.dev/) إطار مفتوح المصدر من Meta لبناء تطبيقات Android وiOS من قاعدة كود واحدة بلغة [JavaScript](https://developer.mozilla.org/en-US/docs/Web/JavaScript) أو TypeScript باستخدام React.** وعلى خلاف موقع ويب داخل غلاف تطبيق، تتحوّل المكونات التي تكتبها وقت التشغيل إلى عناصر واجهة أصيلة من النظام نفسه. ومنذ الإصدار 0.82 (أكتوبر 2025) تعمل كل التطبيقات على **المعمارية الجديدة** — JSI ومحرك العرض Fabric وTurbo Native Modules — التي أزالت الجسر غير المتزامن القديم المسؤول عن معظم شكاوى الأداء التاريخية.

هو الخيار الطبيعي لفريق يكتب React أصلاً. ووفق جدول أسعارنا المنشور، تكلفة تطبيق React Native هي نفسها لأي تطبيق متعدد المنصات: من **5,000–15,000 دولار** للتطبيق البسيط حتى **45,000–100,000 دولار** للمنصة المتقدمة، حتى نوفمبر 2026.

## ما هو React Native؟

React Native إطار مفتوح المصدر من Meta مبني على مكتبة [React](https://react.dev/). تكتب واجهتك بمكونات React المألوفة، ويعرضها React Native بعناصر واجهة نظام التشغيل نفسه لا بصفحات HTML.

ويوضح [توثيق المكونات الأساسية](https://reactnative.dev/docs/intro-react-native-components) هذا التحويل: وقت التشغيل ينشئ React Native عناصر Android وiOS المقابلة لتلك المكونات.

| مكوّن React Native | عنصر Android | عنصر iOS |
|---|---|---|
| `<View>` | `ViewGroup` | `UIView` |
| `<Text>` | `TextView` | `UITextView` |
| `<Image>` | `ImageView` | `UIImageView` |
| `<ScrollView>` | `ScrollView` | `UIScrollView` |
| `<TextInput>` | `EditText` | `UITextField` |

هذا ما يفصل React Native عن التطبيقات الهجينة القديمة المبنية على WebView، والتي كانت مواقع ويب تعمل داخل غلاف تطبيق. الفرق بين الفئتين مشروح في [تطبيق أصيل أم هجين؟](/ar/blog/native-vs-hybrid-app).

## كيف يعمل React Native؟ (المعمارية الداخلية)

منطق تطبيقك — الحسابات والحالة واستدعاءات الشبكة — يعمل بلغة JavaScript، والواجهة ترسمها عناصر أصيلة على خيط واجهة النظام. والمهم هو طريقة تواصل الطرفين.

### المعمارية القديمة: الجسر غير المتزامن

في التصميم الأصلي كان التواصل بين JavaScript والكود الأصيل يمر عبر **جسر** (bridge). وكما يشرح فريق React Native، كان عرض مكوّن أو استدعاء دالة أصيلة يتطلب تحويل الاستدعاء إلى بيانات متسلسلة ووضعه في طابور الجسر ليُعالَج بشكل غير متزامن. هذا سبّب اختناقات مع التحديثات المتكررة والبيانات الكبيرة، وصعّب الوصول إلى 60 إطاراً في الثانية فأكثر، وأنتج أخطاء مثل ظهور فراغات في القوائم أثناء التمرير السريع.

### المعمارية الجديدة: أصبحت الوحيدة

كانت المعمارية الجديدة متاحة اختيارياً منذ الإصدار 0.68، ثم صارت **الافتراضية في 0.76 (أكتوبر 2024)**، ومنذ **[الإصدار 0.82](https://reactnative.dev/blog/2025/10/08/react-native-0.82) (أكتوبر 2025)** أصبحت المعمارية الوحيدة — إعداد `newArchEnabled=false` على Android أو `RCT_NEW_ARCH_ENABLED=0` على iOS يُتجاهل الآن. وكان الإصدار 0.81 آخر إصدار يسمح بالمعمارية القديمة.

وبحسب مقال [The New Architecture is Here](https://reactnative.dev/blog/2024/10/23/the-new-architecture-is-here) تتكوّن من:

- **JSI (JavaScript Interface):** تواصل مباشر بين JavaScript والكود الأصيل بدل الجسر، ويمكن الآن استدعاء الوحدات الأصيلة بشكل متزامن واستلام قيم تشير إلى كائنات أصيلة.
- **محرك العرض الجديد (Fabric):** يخزّن شجرة العناصر بنية ثابتة غير قابلة للتعديل، فيستطيع React العمل على أكثر من نسخة من الواجهة، وإيقاف تحديث منخفض الأولوية لصالح إدخال عاجل من المستخدم، وقراءة التخطيط بشكل متزامن داخل `useLayoutEffect` قبل أن يرى المستخدم الإطار.
- **Turbo Native Modules:** تُحمَّل الوحدات عند الحاجة الفعلية فقط بدل تحميلها كلها عند الإقلاع.

**ماذا يعني هذا عملياً؟** انتقادات الأداء المكتوبة عن نسخة الجسر تصف شيئاً لم يعد يُشحن. قيّم React Native على إصداره الحالي لا على مقال من قبل 2024.

ويسرّع التطويرَ أيضاً [Fast Refresh](https://reactnative.dev/docs/fast-refresh): معظم التعديلات تظهر «خلال ثانية أو اثنتين»، وتُحفظ الحالة المحلية في مكونات الدوال افتراضياً.

## مميزات React Native

- **قاعدة كود واحدة لمنصتين**، مع كود خاص بالمنصة حيث تحتاجه فقط.
- **خبرة الفريق قابلة لإعادة الاستخدام:** مطورو React للويب يعرفون مسبقاً نموذج المكونات والـhooks ومكتبات الحالة والأدوات.
- **مشاركة منطق العمل** بين الويب والجوال (التحقق من المدخلات، نماذج البيانات، عملاء الـAPI).
- **منظومة واسعة:** سجل npm ومكتبات ناضجة للتنقل والحالة والحركة.
- **التحديث عبر الهواء (OTA):** يستطيع [EAS Update من Expo](https://docs.expo.dev/eas-update/introduction/) تحديث «الأجزاء غير الأصيلة» من التطبيق — JavaScript والتنسيق والصور — دون إرسال نسخة إلى المتجر. أما الكود الأصيل والاعتماديات الأصيلة وتغيير الأذونات وترقيات الـSDK فتحتاج نسخة جديدة، ويجب أن تلتزم التحديثات بإرشادات App Store وPlay Store.
- **منفذ للكود الأصيل** لأي جزء يحتاج أداءً خاصاً أو واجهة نظام معيّنة.

## عيوب React Native

- **الرسوم والوسائط الثقيلة جداً:** الألعاب ثلاثية الأبعاد ومعالجة الفيديو المباشرة والرسوم اللحظية المعقدة يخدمها الكود الأصيل أو محرك ألعاب أفضل.
- **الاعتماد على حزم خارجية:** بعض قدرات النظام لا تتوفر إلا عبر حزم مجتمعية قد تتأخر صيانتها.
- **حجم التطبيق:** محرك JavaScript يُشحن داخل التطبيق، فالتطبيق الأدنى أكبر من نظيره الأصيل المجرّد.
- **الترقيات:** الانتقال بين الإصدارات يحتاج عملاً مقصوداً — التحول في 0.82 مثلاً تطلّب أن تدعم كل مكتبة تستخدمها المعمارية الجديدة.
- **ميزات النظام الجديدة تصل متأخرة:** قدرة جديدة في iOS قد تحتاج وحدة أصيلة قبل أن تستخدمها.
- **RTL يحتاج انتباهاً:** واجهة [`I18nManager`](https://reactnative.dev/docs/i18nmanager) تتحكم في التخطيط من اليمين لليسار، لكن `allowRTL` و`forceRTL` لا يسريان إلا عند تشغيل التطبيق التالي، والتوثيق ينصح بعدم فرض RTL في الإنتاج. التطبيقات العربية أولاً يجب أن تخطط لذلك من البداية — راجع [دعم العربية وRTL في React Native](/ar/blog/react-native-rtl-arabic).

## React Native أم Flutter؟

React Native يحوّل مكوناتك إلى عناصر أصيلة ويناسب الفرق التي تكتب React أو تريد مشاركة الكود مع تطبيق ويب مبني بـReact، أما [Flutter](/ar/blog/flutter) فيرسم عناصره بنفسه بلغة Dart ويناسب الفرق الجديدة والمنتجات التي تحتاج نظام تصميم متطابقاً بدقة. المقارنة الكاملة مع إطار القرار في [Flutter مقابل React Native: أيهما تختار لتطبيقك؟](/ar/blog/flutter-vs-react-native). وإن فضّلت أن يُحسم الاختيار على متطلباتك الفعلية، فهذا جزء من طريقة تحديدنا لنطاق [مشاريع تطبيقات الجوال](/ar/services/mobile-apps).

## كم تكلفة تطبيق React Native؟

الإطار لا يغيّر الشريحة السعرية؛ النطاق هو ما يغيّرها. النطاقات التالية من جدول أسعارنا المنشور، حتى نوفمبر 2026:

| الفئة | المدة المعتادة | دولار |
|---|---|---|
| تطبيق بسيط | 6–10 أسابيع | 5,000 – 15,000 |
| تطبيق متوسط التعقيد | 3–5 أشهر | 15,000 – 45,000 |
| تطبيق متقدم أو منصة | 5–9 أشهر | 45,000 – 100,000 |

بالريال السعودي: 18,800–56,300 و56,300–168,800 و168,800–375,000 ريال على التوالي. المنهجية الكاملة مع الدرهم والريال القطري في [تكلفة تطوير التطبيقات في الخليج](/ar/blog/mobile-app-development-cost-gulf).

## متى لا تستخدم React Native؟

تجنّبه إذا كان مشروعك:

- **لعبة** — استخدم Unity أو Godot.
- **يعتمد بشدة على معالجة الوسائط** كتحرير الفيديو أو تأثيرات الكاميرا اللحظية.
- **تطبيقاً بسيطاً لمنصة واحدة** — التطوير الأصيل أخف حينها.
- **يتطلب أحدث ميزات النظام فور إطلاقها** — انتظار دعم الوحدات سيعطّلك.

## الأسئلة الشائعة

### هل ما زال React Native يستخدم الجسر (bridge)؟

لا. منذ الإصدار 0.82 أصبحت المعمارية الجديدة هي الوحيدة، وتُتجاهل الإعدادات التي كانت تعيد تفعيل الجسر القديم. بعض واجهات المعمارية القديمة باقية في الكود للتوافق، وطبقات التوافق ستبقى في المستقبل المنظور، لكن التطبيقات تعمل على JSI ومحرك العرض الجديد.

### أي إصدار جعل المعمارية الجديدة افتراضية؟

الإصدار 0.76 الصادر في أكتوبر 2024. كانت متاحة اختيارياً منذ 0.68، وكان 0.81 آخر إصدار يسمح بتعطيلها، ثم ألغى 0.82 (أكتوبر 2025) هذا الخيار.

### هل أستطيع نشر إصلاح دون مراجعة App Store أو Play Store؟

جزئياً. عبر EAS Update من Expo تستطيع نشر تعديلات JavaScript والتنسيق والصور عبر الهواء. أما تعديل الكود الأصيل أو الاعتماديات الأصيلة أو الأذونات فيحتاج نسخة جديدة عبر المتاجر، ويجب أن تحترم التحديثات إرشادات المتاجر.

### كم تكلفة تطبيق React Native؟

وفق جدول أسعارنا المنشور حتى نوفمبر 2026: من 5,000 إلى 15,000 دولار للتطبيق البسيط، ومن 15,000 إلى 45,000 دولار للتطبيق متوسط التعقيد، ومن 45,000 إلى 100,000 دولار للتطبيق المتقدم أو المنصة. نطاق الخادم والتكاملات يحرّكان الرقم أكثر من الإطار.

### كيف يتعامل React Native مع واجهات العربية من اليمين لليسار؟

عبر وحدة `I18nManager` التي تخبرك إن كان التخطيط RTL وتتيح السماح به أو فرضه. تغييرات `allowRTL` و`forceRTL` لا تسري إلا بعد إعادة تشغيل التطبيق، فتبديل اللغة داخل التطبيق يحتاج مسار إعادة تشغيل. والأيقونات والحركات وبعض مكونات الطرف الثالث تحتاج مراجعة في وضع RTL.

### هل يمكن مشاركة كود React Native مع موقع ويب؟

منطق العمل والأنواع وعملاء الـAPI تُشارَك بسهولة مع تطبيق ويب مبني بـReact. ومشاركة الواجهة نفسها ممكنة عبر مشاريع مجتمعية مثل React Native Web، وهي أنسب للشاشات ذات الطابع التطبيقي منها لصفحات التسويق.
