# RTL في CSS: بناء تخطيطات ثنائية الاتجاه كما ينبغي

ابنِ التخطيط من اليمين لليسار بملف أنماط واحد: ضع `dir="rtl"` و`lang="ar"` على عنصر `<html>`، واكتب كل قاعدة مسافات ومواضع بالخصائص المنطقية — `margin-inline-start` بدل `margin-left`، و`inset-inline-end` بدل `right`، و`text-align: start` بدل `left`. عندها ينعكس التخطيط من تلقاء نفسه، ولا يبقى ملف RTL تحتاج لمزامنته.

الطريقة القديمة كانت ملف أنماط ثانياً — `styles-rtl.css` يُحمَّل للعربية ويتجاوز كل `margin-left` بـ`margin-right`. كانت تعمل، ثم تنحرف عن الأصل، لأن كل مكوّن جديد يحتاج تنفيذين ولا يُختبر إلا أحدهما. يشرح هذا الدليل الطريقة الحديثة بالتفصيل. وللنطاق الأوسع لدعم العربية راجع [الدليل الكامل لتعريب التطبيقات والمواقع](/ar/blog/arabic-localization-guide)؛ والواجهات ثنائية اللغة المبنية بهذه الطريقة هي الأساس في [خدمات تطوير الويب](/ar/services/web-development) لدينا.

## اضبط الاتجاه مرة واحدة وبشكل صحيح

الاتجاه مكانه عنصر `<html>` بجوار اللغة:

```html
<html lang="ar" dir="rtl">
```

**الخاصيتان مهمتان معاً.** `dir` يضبط الاتجاه الأساسي للتخطيط ولخوارزمية الاتجاه؛ و`lang` يوجّه اختيار الخط وتقسيم الكلمات ونطق قارئات الشاشة. و[إرشادات W3C](https://www.w3.org/International/questions/qa-html-dir) صريحة في أن `lang` لا يضبط الاتجاه — تحتاج `dir` دائماً.

**لا تضبط الاتجاه الأساسي عبر CSS.** المقال نفسه ينص: «لا تستخدم CSS لتطبيق الاتجاه الأساسي في صفحات HTML». فالاتجاه قد يغيّر معنى المحتوى، ومكانه الترميز. خاصية `direction` موجودة في CSS، لكن الخاصية في HTML هي المرجع.

## الخصائص المنطقية: السر كله

الخصائص الفيزيائية تشير إلى جهات ثابتة. أما المنطقية فتشير إلى *بداية* سطر النص و*نهايته*، وهما تتبادلان تلقائياً في RTL.

| فيزيائية | منطقية |
|---|---|
| `margin-left` | `margin-inline-start` |
| `margin-right` | `margin-inline-end` |
| `padding-left` | `padding-inline-start` |
| `padding-right` | `padding-inline-end` |
| `border-left` | `border-inline-start` |
| `left` / `right` | `inset-inline-start` / `inset-inline-end` |
| `text-align: left` | `text-align: start` |
| `border-top-left-radius` | `border-start-start-radius` |
| `width` / `height` | `inline-size` / `block-size` |

**والصيغ المختصرة مريحة:**

```css
.card {
  margin-inline: 1rem 2rem;   /* البداية، النهاية */
  padding-block: 1rem;        /* أعلى وأسفل */
  border-start-start-radius: 8px;
}
```

**دعم المتصفحات لم يعد عائقاً.** يصنّف MDN خاصية [`margin-inline-start`](https://developer.mozilla.org/en-US/docs/Web/CSS/margin-inline-start) ضمن Baseline «متاحة على نطاق واسع»، وتعمل عبر المتصفحات منذ يناير 2020. وراجع جدول التوافق في MDN للصيغ المختصرة الأحدث إن كنت تدعم أجهزة قديمة.

**استراتيجية الانتقال التي تنجح:** أضف قاعدة lint ترفض الخصائص الفيزيائية في الكود الجديد (لـStylelint إضافات لذلك)، وحوّل المكوّنات القائمة كلما لمستها. إعادة الكتابة الشاملة نادراً ما تكون مبررة؛ والانحراف يتوقف لحظة يكفّ الكود الجديد عن الإضافة إليه.

## Flexbox وGrid ينعكسان مجاناً

هذا ما لا يتوقعه كثيرون: **تخطيطات flex وgrid تتبع اتجاه السطر**، فتنعكس في RTL دون أي كود إضافي.

```css
.toolbar {
  display: flex;
  gap: 1rem;
  justify-content: flex-start;  /* الحافة اليمنى في صفحة RTL */
}
```

`flex-start` و`flex-end` و`justify-content` وخطوط `start`/`end` في grid كلها تتبع اتجاه النص.

**وحين يجب ألا ينعكس صف ما** — أزرار مشغّل الوسائط مثلاً — أعطِ تلك الحاوية اتجاهها في الترميز:

```html
<div class="player-controls" dir="ltr">…</div>
```

**وتجنّب `row-reverse` كحل لـRTL.** فهو يعكس في *الاتجاهين*، والتخطيط المعتمد عليه سيكون خاطئاً في أحدهما.

## ما يجب ألا ينعكس أبداً

العكس التلقائي أداة غير دقيقة. هذه تحتفظ باتجاهها في كل اللغات:

- **أزرار الوسائط** — زر التشغيل يشير لليمين
- **الساعات والمؤقتات**
- **الرسوم البيانية ذات المحور الزمني**
- **أرقام الهواتف والآيبان والبطاقات والإصدارات**
- **مقاطع الكود ومخرجات الطرفية**
- **معظم الشعارات**

**لمقاطع الكود،** حدّدها من اليسار لليمين في الترميز حيث تتحكم فيه:

```html
<pre dir="ltr"><code>const total = items.reduce(sum, 0);</code></pre>
```

وحين تأتي مقاطع الكود من محوّل Markdown لا تستطيع التعديل على مخرجاته، فقاعدة في ملف الأنماط هي البديل العملي:

```css
pre {
  direction: ltr;
  text-align: left;
  unicode-bidi: isolate;
}
```

دون أحد هذين، يُعرض الكود داخل المقال العربي والعوامل وعلامات الترقيم في الأطراف الخاطئة من الأسطر.

**وللأيقونات،** اعكس الاتجاهية منها فقط:

```css
[dir="rtl"] .icon-arrow-back,
[dir="rtl"] .icon-chevron-next {
  transform: scaleX(-1);
}
```

لا تطبّق هذا على كل الأيقونات. زر تشغيل أو ساعة معكوسة هو تحديداً الخطأ الذي يمنعه هذا القسم.

## قواعد طباعة مختلفة

ثلاث قواعد CSS أهم للعربية من اختيار الخط نفسه.

**`letter-spacing` يجب أن يكون صفراً.** تنبّه [صفحة MDN لخاصية `letter-spacing`](https://developer.mozilla.org/en-US/docs/Web/CSS/letter-spacing) إلى أن النص المكتوب بالحرف العربي يُتوقع أن تبقى حروفه المتصلة متصلة، وأن تباعد الحروف «قد يجعل النص يبدو مكسوراً». أعد ضبطه للعربية، لأنه يأتي عادةً من نمط عناوين صُمّم للحرف اللاتيني.

```css
:lang(ar) {
  letter-spacing: 0;
  line-height: 1.8;
}
```

**ارتفاع السطر يحتاج مساحة أكبر.** قيمة 1.4–1.5 المريحة بالإنجليزية تبدو خانقة بالعربية؛ و1.7–1.8 نقطة انطلاق أفضل للنص الأساسي. ويشرح [دليل الخطوط العربية على الويب](/ar/blog/arabic-web-fonts) السبب، ويغطي التحميل والتقليص.

**`text-transform` بلا فائدة.** العربية بلا حروف كبيرة وصغيرة، فلا يغيّر `uppercase` شيئاً في النص العربي — لكنه يغيّر أي نص لاتيني مضمّن، وغالباً دون قصد.

## النص ثنائي الاتجاه والمحتوى المضمّن

الجمل العربية التي تحتوي أسماء منتجات إنجليزية أو أرقاماً أو روابط تحتاج عزلاً، وإلا وقعت علامات الترقيم في مواضع خاطئة بصرياً.

**استخدم `<bdi>` لأي نص مضمّن لا تعرف اتجاهه مسبقاً:**

```html
<p>اشترِ <bdi>iPhone 15 Pro</bdi> الآن.</p>
```

يصف [MDN عنصر `<bdi>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/bdi) بأنه يطلب من خوارزمية الاتجاه في المتصفح معالجة محتواه بمعزل عن محيطه، ويذكر أنه يتصرف كأن `dir="auto"` مضبوط عليه. وهذا ما تريده لأسماء المستخدمين وعناوين المنتجات ونتائج البحث. كما ينصح MDN بعدم محاكاته بـ`unicode-bidi: isolate` على `<span>`، لأن طريقة CSS ليست دلالية.

**وحين تعرف الاتجاه، صرّح به:**

```html
<span dir="ltr">+966 50 123 4567</span>
```

ويغطي [دليل الأرقام والعملات والصيغ](/ar/blog/arabic-numerals-formats) هذا بعمق، بما فيه واجهات `Intl` التي تنسّق العملة بشكل صحيح.

## الاختبار

**اختبر مبكراً لا قبيل الإطلاق.** تحويل مشروع ناضج إلى RTL لأول مرة يكشف عشرات الأعطال الصغيرة دفعة واحدة. فعّله في الأسبوع الأول.

**فحص سريع دون تغيير تطبيقك:** اضبط `dir="rtl"` على `<html>` من أدوات المطور وتنقّل في الواجهة. معظم أخطاء التخطيط تظهر فوراً.

**أتمت فحص التراجع.** لقطات اختبار بصري في الاتجاهين تلتقط المكوّن الذي كسرته إعادة هيكلة في أحدهما دون أن ينتبه أحد.

**ما تبحث عنه تحديداً:**
- الظلال والتدرجات ذات الإزاحة الاتجاهية
- العناصر ذات الموضع المطلق التي تستخدم `left`/`right`
- مواضع صور الخلفية
- نقاط أصل التحويلات (transform-origin)
- موضع التمرير في الحاويات ذات التمرير الأفقي
- محتوى `::before`/`::after` المحدد بمواضع فيزيائية

## الأسئلة الشائعة

### هل أحتاج ملف أنماط RTL منفصلاً؟

لا. الخصائص المنطقية مثل `margin-inline-start` تُحسب صحيحاً في الاتجاهين من ملف أنماط واحد. أما ملف RTL المنفصل فينحرف عن الأصل كلما أُضيفت مكوّنات، لأن نسخة واحدة فقط تُختبر عادةً.

### هل أعتمد على الخصائص المنطقية في بيئة الإنتاج؟

نعم للخصائص الأساسية. يصنّف MDN خاصية `margin-inline-start` ضمن Baseline «متاحة على نطاق واسع»، وتعمل عبر المتصفحات منذ يناير 2020. وراجع جداول التوافق لأي صيغة مختصرة أحدث تستخدمها مقابل أقدم متصفح تدعمه.

### هل ينعكس Flexbox تلقائياً في RTL؟

نعم. flex وgrid يتبعان اتجاه السطر، فتتبع `flex-start` و`justify-content` وخطوط grid قيمة `dir` تلقائياً. ولا تستخدم `row-reverse` حلاً لـRTL — فهو يعكس في الاتجاهين وسيكون خاطئاً في أحدهما.

### أضبط الاتجاه بخاصية `dir` أم بخاصية `direction` في CSS؟

بخاصية `dir`. تنصح W3C بعدم استخدام CSS لتطبيق الاتجاه الأساسي في HTML، لأن الاتجاه جزء من معنى المحتوى. استخدم `dir="rtl"` على `<html>` و`dir` على عناصر محددة، واترك `direction` في CSS للحالات البديلة مثل مقاطع الكود المولّدة التي لا تستطيع التعديل عليها.

### لماذا يبدو عنواني العربي مكسوراً؟

على الأرجح بسبب `letter-spacing`، الموروث غالباً من نمط عناوين في نظام التصميم. الحروف العربية متصلة، وأي تباعد غير صفري يفصلها. اضبط `letter-spacing: 0` للنص العربي، بقاعدة `:lang(ar)` مثلاً.

### كيف أمنع تكسّر مقاطع الكود في صفحة RTL؟

حدّدها من اليسار لليمين: `<pre dir="ltr">` حيث تتحكم في الترميز، أو قاعدة `pre { direction: ltr; text-align: left; unicode-bidi: isolate; }` للمحتوى المولّد من Markdown. دون ذلك تنتهي العوامل وعلامات الترقيم في الأطراف الخاطئة من الأسطر.

### كيف أختبر RTL دون تحويل التطبيق كله؟

اضبط `dir="rtl"` على عنصر `<html>` من أدوات المطور وتنقّل في الواجهة. معظم أخطاء التخطيط تظهر فوراً. وللحماية المستمرة أضف لقطات اختبار بصري في الاتجاهين.

## الخلاصة

`dir` و`lang` على `<html>`، وخصائص منطقية في كل مكان، وflex وgrid يتبعان الاتجاه وحدهما، وقائمة قصيرة صريحة بما يحتفظ باتجاهه. أضف `letter-spacing: 0` وارتفاع سطر أكبر و`<bdi>` للنص المضمّن، ويخدم ملف أنماط واحد اللغتين.

وإن كان لموقعك ملف RTL منفصل وتريد خطة للتخلص منه، [راسلنا بتفاصيل التقنيات التي تستخدمها](/ar/contact) ونرسم لك خطوات الانتقال.
